Subsplash embed ──(browser metadata pass)──▶ manifest ──subsplash-sidecars──▶ ARCHIVE/rcc-sermons/<date>-<slug>/ (sidecar.json + youtube.txt) ✅ DONE └── video.mp4 / audio.mp3 ⛔ needs a decision (below) media + sidecar ──upload-youtube──▶ YouTube (playlist per series) ⛔ gated on channel + API (#10) records ──build-podcast-feed──▶ /podcast.xml

Media bytes — what I learned tonight (tried browser-native downloads). The embed's public Download button works, but with two hard limits discovered in practice:

  • Audio only. That button downloads the MP3 — there is no public video download. Video (the actual YouTube-migration payload) isn't reachable from the public embed.
  • Gated on a stalling player. The button stays disabled until the Subsplash video player finishes loading, and that player stalls (readyState 0) in the automation context. Result: 3 of 15 audio files landed on the drive (they buffered during extended interaction); the rest are unreliable to script.

Recommendation → the Subsplash dashboard (you own the account). It's the only reliable source for video, and it sidesteps the player-gating entirely. Log in and I can pull audio + video from there, or bulk-export; the existing subsplash-fetch / upload-youtube scripts take over from the files. The metadata + sidecars for all 15 are already staged and waiting for the bytes.
